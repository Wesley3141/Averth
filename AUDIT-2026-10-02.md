# Averth hostile product audit — 2026-10-02

Auditor posture: brutal. Every claim below was verified by running code or
reading source, not by trusting docs. File:line references are to the repo
at `~/workspace/averth` as of 2026-10-02 (git HEAD `d5a5524` era).

## Verdict up front

**The meter math is trustworthy. The product is demo-ready for a friendly
diagnostic conversation, but NOT rock-solid.** Three critical problems would
embarrass us in front of a sharp prospect:

1. The budget-breach hook — the seed of the governance story — never fires
   for failed attempts, i.e. it is blind to the runaway tail the whole pitch
   is about.
2. Every dollar figure rests on frozen price tables with no refresh
   mechanism, no effective dates, and no staleness warning. Vendor price
   changes silently corrupt all output.
3. The single most influential number in the demo's headline finding is an
   unmeasured assumption ($70/hr loaded labor), not data.

Wesley's worry ("we built it too quick and it may not actually work") is
half-right: the core metering genuinely works and the demo is not rigged.
What was built too quick is the pricing/governance layer around it.

## Ranked bug list

### CRITICAL

**C1. Budget-breach hook never fires for failed attempts — blind to the runaway tail.**
`averth/tracker.py:297`: `if success and self.budget_per_success and ...`.
A failed runaway (the 2%-burns-60% shape the entire pitch is built on)
exceeds budget silently: no callback, no exception. Verified:
```
failed runaway $1.29 over $1.00 budget → breach fired: [] (nothing)
successful $1.29 over $1.00 budget     → breach fired: ['ok-over']
no-callback failed over-budget         → NO exception raised
```
The "kill switch" narrative's seed can't see the kills that matter.
Repro: 5-line script above (any Tracker with budget_per_success + failed
over-budget attempt).

**C2. All pricing is frozen at build time; no refresh mechanism exists, and
staleness is silent.**
- `averth/pricing.py`: `MODEL_PRICES` (12 models), `TOOL_PRICES` (8 tools)
  are literal dicts with no effective date, no version, no source URL.
- There is deliberately no network code in the package (verified by grep),
  so "live" pricing is architecturally impossible today — and there is no
  `pricing.refresh()`, no staleness warning, nothing.
- Reports (`report_text`, `write_html`) never stamp which price table was
  used. A prospect cannot tell whether the dollars assume October 2026 or
  2024 prices.
- Failure mode: when a vendor changes a price for a *known* model, every
  dollar figure silently goes wrong. (Unknown models fail loudly via
  KeyError → flagged estimate, which is the correct behavior and works.)
- Be straight about the fix: public free "live vendor price feeds" don't
  exist. The achievable bar is a **dated, versioned price table + staleness
  warning + one-command update + price-vintage stamped on every report**.
  Today we have none of the four.

**C3. The headline demo finding is driven by an unmeasured assumption, not data.**
`averth/pricing.py:27`: `HUMAN_COST_PER_MIN = 1.17` (~$70/hr loaded).
In the current demo, "TOP FINDING [HIGH]: Human review is 63% of
fully-loaded cost ($803.27)" — that 63% is downstream of this default,
which no prospect's environment measured. At $30/hr loaded labor the
finding roughly halves. The single most decision-relevant number in the
report is the least measured. At minimum the report must label the labor
rate as an assumption and prompt for the prospect's real number; better,
make it a required input for the headline claim.

### HIGH

**H1. Importer docstring contradicts Tracker on branch-retry semantics.**
`averth/importers/common.py` EVENT schema docs: branch retry marks "all of
that branch's steps, past and future" as waste. `Tracker.log_retry`
(`tracker.py:196-232`): marks past steps only; future work on the branch
"starts fresh." The importer passes `branch=` straight through, so behavior
= past-only. Either the docs or the code is wrong; a customer reading the
importer docs will mispredict their yield numbers.

**H2. `TOOL_PRICES` defaults are arbitrary per-deployment numbers baked in
as universals.** `web_search: $0.005`, `browser_action: $0.010`, etc.
(`pricing.py:17-26`). Any trace that doesn't supply explicit tool costs
silently gets these. Enrichment/sandbox spend — the layer the validation
report itself calls "invisible on provider invoices" — is exactly where a
wrong default does the most damage.

**H3. `CACHE_READ_DISCOUNT = 0.10` silently applied to all vendors.**
(`pricing.py:33`). 10% is Anthropic's published cache-read rate; other
vendors differ. The comment admits this, but the code applies it unless the
caller overrides — a silent cross-vendor assumption in a dollar figure the
report presents as savings.

**H4. Stale demo numbers in external circulation.** See checklist item 4:
$0.03/$0.62 no longer matches the demo ($0.20/$0.82). The 61% tail claim
is still accurate.

### MEDIUM

**M1. `FALLBACK_PRICE = (1.00, 3.00)` duplicates `ESTIMATED_MODEL_PRICES`.**
`importers/common.py:61` vs `pricing.py:40`. Same tuple in two files; update
one and the other silently diverges.

**M2. `guess_provider()` name-guessing can misattribute spend.**
`importers/common.py:64-76`: any model name containing "gpt" → OpenAI
pricing. A fine-tuned/proxied "gpt-custom" gets OpenAI list prices
silently.

**M3. `Tracker.__init__`: `human_cost_per_min or pricing.HUMAN_COST_PER_MIN`.**
Passing explicit `0` falls back to the default instead of honoring it
(`tracker.py:110`).

### LOW / noted (not bugs, but a prospect may ask)

- `simulate_policy` uses strict `>`; a run exactly at the cap is not
  stopped. Defensible, but document the boundary.
- `yield_ratio` reports 1.0 for attempts with zero tokens (tool-only runs).
- No thread-safety in Tracker / LangChain handler (already documented as
  known limitation #15 in VALIDATION.md).
- `insights.py` materiality thresholds (15%, 40%, $1.00 floor, etc.) are
  judgment calls — documented as such in code comments; fine.

## What the audit did NOT find (Wesley's fear, answered)

- The meter is not fake. Cost attribution, the terminal/retry identity,
  yield math, context-tax math, and tail percentiles all check out against
  independent hand calculation.
- The demo is not rigged. Seeded RNG, computed output, deterministic.
- The policy simulator is not theater. It replays honestly, including the
  collateral-damage accounting most vendors would hide.
- 46 real trace units processed with zero hand-fixing (per VALIDATION.md,
  corroborated by the trace dirs and regression tests). The "one real
  production trace" milestone is substantially met on public/validation
  traces — **not yet on a customer production trace**, which remains the
  open milestone.
- Nothing implies active enforcement: TERMS.md:11 disclaims it, README
  marks the hook "Phase-1 (built only after a buyer confirms…)", the MCP
  privacy page says "never enforces anything."

## Recommended fix order before any paid pilot
1. C1: fire the breach hook on failed attempts over budget (or document why
   per-success semantics exclude them — but the current silence is wrong).
2. C2: version/date the price table, warn on staleness, stamp price vintage
   on reports.
3. C3: label the labor rate as an assumption in the report; prompt for the
   prospect's real loaded rate.
4. H1–H4, then M1–M3.

## Demo-ready verdict
**Yes for a friendly diagnostic conversation; no for "rock solid."**
The numbers the demo shows are honestly computed and the findings are
behavior-changing. But a VP Finance prospect — the actual buyer — will ask
"whose labor rate is that?", "how current are these model prices?", and
"does the budget hook catch failed runaways?" Today all three answers are
bad. Fix C1–C3 and the product survives hostile diligence.
